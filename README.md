# Портъ-Артуръ и Дальнiй

Сайт об историческом Даляне и Порт-Артуре: каталог заметок Telegram-канала [t.me/portartur_dalnii](https://t.me/portartur_dalnii), лица, библиотека, карта и маршруты. Русские оригиналы заметок доступны во всех языковых версиях. Редакционные аннотации и справки публикуются на языке страницы. Ссылки на Telegram ведут к публикациям и обсуждению.

Прототип: https://nikitadalian.github.io/PortArturDalnii/

## Как устроено

- Astro 7, статический сайт. Публикация на GitHub Pages идёт автоматически при пуше в `main` (`.github/workflows/deploy.yml`).
- Поиск — Pagefind: отдельный индекс для каждой опубликованной языковой редакции. При недоступности индекса работает запасной поиск по данным сайта.
- Карта — MapLibre GL с подложкой OpenStreetMap.
- Данные лежат в `src/data/*.json`, адреса и общие функции — в `src/lib/data.ts`, стиль — в `src/styles/global.css`, правила для разработки — в `STYLE.md`.

## Обновление материалов

1. Выгрузить канал из Telegram в JSON и положить рядом с папкой сайта (`../TGArchive`).
2. Обновить карточки в `../work/*.json`.
3. `python scripts/build_data.py` — сводит данные в `src/data/` с едиными слагами.
4. `python scripts/build_images.py` — готовит фото: WebP и водяной знак со ссылкой на канал.
5. Обновить русские оригиналы заметок из выгрузок командой `python scripts/import_telegram_originals.py`. Чтобы явно задать полный набор выгрузок, указать `--archive` перед каждым путём к `result.json`. Флаг `--check` сверяет результат с сохранённым JSON без записи.
6. Проверить редакционные тексты и обновить английские и китайские аннотации и справки (см. ниже).
7. Собрать сайт и выполнить проверки.

Команды выполняются из папки `site`; нужен Node.js версии, указанной в `package.json`:

```sh
npm run build
npm run check
```

`build` собирает включённые языки и их индексы Pagefind. `check` проверяет исходные связи, схемы и актуальность переводов, затем ссылки, якоря, заголовки и атрибуты изображений в `dist`. Для локальной разработки запускать сервер в фоне: `npm run dev -- --background`; управление — `npm run astro -- dev status`, `npm run astro -- dev logs`, `npm run astro -- dev stop`.

Сборка в отдельную папку и её проверка:

```sh
npm run build -- ../.builds/reader-update
node scripts/check_data.mjs
node scripts/check_i18n.mjs
node scripts/check_mentions.mjs
node scripts/check_links.mjs ../.builds/reader-update
```

Манифест содержит проверенные аннотации, связи и подписи изображений. Импорт пропускает уже опубликованный пост 251, сохраняет 11 новых заметок и назначает 48 фотографиям свободные номера 344–391: номера внутри новой Telegram-выгрузки начинаются заново. Оригиналы сохраняются в `../TGArchive/photos`, карточки — в `../work`; `build_data.py` пересчитывает обратные связи и серии. Повторный запуск не добавляет дубликатов. Для подготовки WebP используется Pillow; шрифт с кириллицей можно задать через `--font`.

## Статьи о местах

Три развёрнутые статьи размещены на существующих страницах площади Чжуншань, гавани Порт-Артура и укрепления № 5. Тексты, подписи, источники и связи хранятся в `src/components/places/dossiers.ts`. Это самостоятельные редакционные статьи по нескольким постам; краткие карточки исходных заметок сохранены.

`PlaceDossier.astro` выводит оглавление, названия, разделы со ссылками на источники и запись для цитирования. `DossierLinks.astro` добавляет обратные переходы из заметок, биографий и библиотеки. Подборку на главной формирует `home/ReadFirst.astro`. Новая статья должна ссылаться на существующую страницу места; номера в `refs` и `figure.source` соответствуют порядку массива `sources` (с единицы). Не заменять источник пересказом и не добавлять неподтверждённые номера страниц или атрибуции изображений.

### Проверка источников и чтение документов

`src/data/guide_evidence.json` хранит редакционные проверки, ключ записи — слаг статьи о месте. Типы заданы в `src/lib/evidence.ts`. `GuideEvidence.astro` показывает результаты проверки и изменения редакции, `SourceAssessment.astro` — сведения о работе с отдельным источником.

- У проверки есть постоянный `id`, существующий идентификатор раздела статьи в `section`, краткий результат `finding` и номера `refs`. Нумерация совпадает с массивом `sources` самой статьи о месте, начиная с единицы.
- Статус `confirmed` относится к конкретному проверенному утверждению; `attributed` означает, что сведения приведены по указанной публикации; `unresolved` сохраняет открытый вопрос. Каталог, библиография и пересказ не подтверждают, что редактор просмотрел оригинальный документ.
- Для источника указываются его номер `ref`, канонический `url`, тип (`primary`, `catalogue`, `field`, `secondary`), точное место в документе в `locator`, фактически просмотренное в `inspection` и необходимые оговорки в `note`. `url` должен совпадать с `guide.sources[ref - 1].url`: `validateReview` проверяет это и останавливает сборку при расхождении. При добавлении или перестановке источников в статье сверить и номера, и URL проверок во всех языках, чтобы старый номер не начал указывать на другую публикацию. Каталожная запись или зеркало могут вести к историческому документу, но не становятся от этого оригинальным архивом.
- `checkedAt` — дата проверки в ISO-формате, `editor` — редакторская подпись, `scope` — фактический объём работы. В `revisions` кратко записывается, что уточнено. Не обновлять дату ради видимости свежей проверки.

`src/data/document_readings.json` добавляет короткое чтение документа на существующую страницу источника. Ключ — слаг из `sources.json`; сейчас разбор плана находится на `/biblioteka/istochniki/zodchiy-plan-dalnego-1904/#document-reading`. Новая дублирующая статья для него не нужна. `DocumentReading.astro` выводит изображение, разборчивую оригинальную надпись, перевод и пояснение.

В записи сохраняются `photo` из существующего каталога, `original`, `originalLanguage`, перевод, примечание к транскрипции и короткие разделы. `guide` указывает связанное место. Номера `sections[].refs` относятся к собственному массиву `sources` разбора, а не к источникам статьи о месте. Идентификаторы разделов должны быть уникальны. URL источников, номера ссылок, идентификатор изображения, оригинальная надпись и её язык одинаковы во всех редакциях.

В оригинал включать только действительно прочитанный фрагмент. Неразборчивые слова не восстанавливать по смыслу. План позволяет обсуждать замысел, но сам по себе не доказывает завершение строительства; библиографически найденные страницы отмечать как такие, пока не просмотрены оригинальные полосы. Пояснение должно помогать читателю увидеть документ; пределы проверки достаточно собрать в примечании к транскрипции и сведениях об источниках. Поле `rights` описывает известные условия и происхождение изображения, не создавая новых разрешений на чужие материалы.

После изменения проверки или разбора обновить соответствующие JSON в обеих опубликованных языковых редакциях. После изменения подписей компонентов проверить `ui.json`. Затем выполнить проверки данных и переводов и просмотреть готовый блок на ширине телефона, ссылки к разделам, источникам и обратно к месту.

Шапки статей используют три отдельные иллюстрации: `city`, `harbor`, `fort`. Промпты сохранены в `scripts/guide-art-prompts.json`; изображения создаются отдельно и кладутся в `../work/guides-art/{city,harbor,fort}.png`. Команда `node scripts/build_guide_images.mjs` готовит шесть WebP шириной 1600 и 800 пикселей в `public/img/guides/`. Скрипт только обрабатывает готовые PNG. `DossierHero.astro` выводит подпись: это редакционная иллюстрация с помощью ИИ, а не историческая реконструкция.

## Справки и мини-карты

Для 64 имён и 35 географических названий из `index_terms.json` созданы 99 страниц `/spravochnik/{people|geo}/{slug}/`. Краткие тексты лежат в `src/data/reference_descriptions.json`; страницы показывают связанные заметки и ссылки на исходные публикации. Из указателя и поиска можно перейти прямо к справке. При добавлении термина нужна справка с тем же ключом; `check_data.mjs` обнаруживает пропуски и лишние записи.

`MiniMap.astro` открывает карточку по нажатию на маркер: название, до двух предложений из описания места и ссылка на его страницу. Можно передать собственное поле `summary`; иначе описание подбирается из данных места. Название не служит ссылкой само по себе. Всплывающую карточку можно закрыть кнопкой или Escape.

### Упоминания внутри текста

`LinkedText.astro` превращает найденные имена и названия в обычные ссылки на биографию, место или справку. Исходный текст сохраняется дословно; без JavaScript ссылки ведут на полную страницу. `EntityPreviews.astro` дополняет их краткой карточкой при наведении или клавиатурном фокусе. На сенсорном устройстве нажатие открывает карточку, из неё можно перейти на полную страницу. Карточка закрывается кнопкой, Escape или нажатием вне неё; стрелка вниз переводит фокус со ссылки в карточку.

Реестр в `src/lib/mentions.ts` использует названия, краткие имена и фамилии из общих данных. Дополнительные варианты лежат в `src/data/entity_aliases.json`, отдельно для `ru`, `en`, `zh`. Добавлять только формы, действительно встречающиеся в тексте: склонения, исторические названия и варианты транслитерации. Не генерировать все возможные формы. У каждого языка должны быть ключи всех людей и мест, включая справочные; пустой массив допустим.

`mentionMatcher.ts` сначала ищет длинные совпадения, соблюдает границы латинских и кириллических слов и допускает китайские имена без пробелов. Неоднозначное имя остаётся текстом, если контекст не выделяет ровно одну подходящую сущность. Цитаты пропускаются. Общий `mentionContext()` позволяет исключить ссылку на текущую сущность и повторные ссылки в нескольких абзацах; по умолчанию один вызов связывает не больше четырёх упоминаний. Отдельные исключения не дают спутать лейтенанта Артура с Порт-Артуром и Дальний с Дальним Востоком.

Описания карточек берутся централизованно из биографий, описаний мест и `reference_descriptions.json`, с сокращением до первых двух предложений. Для основных сущностей используются портрет или первое фото места. Подборка изображений для справочных записей хранится в `src/data/reference_media.json`: ключ справки → файл из каталога `photos.json`. Добавлять туда только проверенные изображения с подходящей связью и корректной подписью; отсутствие фото допустимо. Не подставлять случайный снимок соседнего объекта.

После изменения сущностей или вариантов имён запускать `node scripts/check_mentions.mjs` (также входит в `npm run check`). Проверка охватывает сохранность текста, неоднозначность, самоссылки, повторы, цитаты, китайские совпадения и полноту ключей вариантов. После сборки вручную проверить новые совпадения и отсутствие ложных ссылок во всех затронутых языках, обычный переход без JavaScript, наведение, клавиатуру и сенсорную карточку.

## Языковые редакции

`scripts/build_multilingual.mjs` последовательно собирает RU в корень результата, EN в `/en/`, ZH в `/zh/`. После каждой сборки запускается Pagefind для её каталога, до добавления следующего языка. Папка `public` копируется только русской сборкой; переводы используют общие изображения, шрифты и видео через `assetUrl()`. Статические маршруты и слаги общие для всех языков, а переключатель сохраняет путь страницы.

Флаги `src/i18n/releases.json` управляют выпуском EN и ZH: `true` включает редакцию в сборку и переключатель, `false` скрывает её и исключает из сборки. Русская редакция собирается всегда. Перед выпуском перевода нужны редакционная сверка, проверки и просмотр готовых страниц.

### Данные и интерфейс

В `src/i18n/en/` и `src/i18n/zh/` находятся переводы 14 файлов из `src/data/`: `articles`, `books`, `people`, `places`, `routes`, `series`, `sources`, `photos`, `seasons`, `index_terms`, `reference_descriptions`, `layers`, `guide_evidence`, `document_readings`. Структура JSON, ключи, порядок элементов и типы значений должны соответствовать исходникам. Переводятся тексты; слаги, перечисления, числовые значения, координаты, идентификаторы, ссылки на источники и связи сохраняются. ISO-даты не меняются, отображаемые даты можно локализовать. В проверках и разборах неизменны также `id`, `section`, `status`, `ref`, `refs`, `checkedAt`, `photo`, `guide`, `original` и `originalLanguage`. Оговорки о достоверности и неподтверждённые атрибуции нужно сохранять в переводе.

Переводы трёх статей хранятся отдельно в `guides.json`, с ключами-слагами мест. `src/i18n/guides.ts` накладывает текст на русские статьи, сохраняя исходные идентификаторы разделов, ссылки, номера источников и изображения. Состав разделов и порядок источников должны совпадать.

`ui.json` — словарь «точная русская строка или фрагмент → перевод». `scripts/i18n-integration.mjs` выбирает локальные JSON до компиляции, а интерфейс переводит после компиляции Astro: через AST меняет строковые литералы и текстовые части шаблонов. Идентификаторы, выражения, комментарии и CSS не редактируются. Для встроенных фрагментов используются границы слов; приоритет у длинных совпадений. Пробелы, переносы и HTML-сущности важны: после правки русского интерфейса проверять фактический результат сборки, включая подписи доступности и клиентские сообщения.

### Сверка после изменения оригинала

`source-manifest.json` каждой редакции хранит SHA-256 исходных файлов: 14 JSON, перечисленных выше, и `components/places/dossiers.ts` — всего 15 записей. Список задаёт `scripts/translation_sources.mjs`; перед хешированием окончания строк CRLF приводятся к LF. Если оригинал изменился, `check_i18n.mjs` останавливает проверку опубликованной редакции до сверки перевода. Манифест фиксирует сверенную версию оригинала, а не подтверждение исторических утверждений.

Сначала сверить изменённые русские материалы и поправить перевод. Только после редакционной проверки зафиксировать новую исходную редакцию:

```sh
node scripts/mark_translation_reviewed.mjs en
node scripts/mark_translation_reviewed.mjs zh
```

Запускать команду только для проверенного языка. Она записывает хеши, но сама не переводит и не проверяет качество текста; использовать её просто для устранения ошибки проверки нельзя. `ui.json` в этот манифест не входит, поэтому изменения интерфейса дополнительно сверяются по страницам. После сверки повторить сборку и проверки.

## Переезд на свой домен

В `astro.config.mjs` заменить `site` на новый адрес, а общий префикс `/PortArturDalnii` в `base` — на префикс нового размещения. Языковые суффиксы `/en` и `/zh` сохранить. Внутренние ссылки строятся через `url()` и `href.*`, общие ресурсы — через `assetUrl()`. После изменения проверить сборку всех включённых редакций и их ссылки.
